# BouncyHSM: test findings from pkcs11-check

**Date:** 2026-03-23
**Module:** BouncyHSM 2.0.1 (.NET/BouncyCastle, v3.2, 206 mechanisms)
**Test tool:** pkcs11-check (dev branch)
**Total tests:** 72,634
**Results:** 51,354 passed, 162 failed, 8,023 skipped, 13,088 xfailed, 7 errors

## Crashes (7) - large data operations

All crashes occur on operations with 1MB+ data:
- `test_blake2.py::TestBlake2bProperties::test_large_data`
- `test_buffers.py::TestDigestBufferSizes::test_large_input`
- `test_buffers.py::TestEncryptBufferSizes::test_1mb`
- `test_digest.py::TestDigestProperties::test_digest_large_data`
- `test_large_objects.py::TestLargeEncryption::test_encrypt_1mb_aes_cbc`
- `test_multipart_streaming.py::TestMultipartDigest::test_sha256_large_data`
- `test_multipart_streaming.py::TestMultipartDigest::test_sha512_1mb_crossverify`

Root cause: `TcpHostedService.cs:78` uses a single `ReceiveAsync` call to read
the request body, but TCP may deliver large payloads in multiple chunks. For
1MB+ data, the server receives only a partial message and fails during
MessagePack deserialization.

Fix: replace the single `ReceiveAsync` with a read loop that accumulates bytes
until `bodySize` is fully received. File: `src/Src/BouncyHsm/Infrastructure/
HostedServices/TcpHostedService.cs`, lines 77-78.

Also: `TimeSpanToTimeout` (line 112) uses `.Milliseconds` instead of
`.TotalMilliseconds` - a separate bug that would truncate timeouts.

## Bugs

### Critical

**Non-deterministic HMAC output** - `test_fuzz.py::TestHMACFuzz`
- Hypothesis found inconsistent HMAC results when replaying the same test case
- Same key + same data must always produce the same MAC
- `hypothesis.errors.FlakyFailure: Inconsistent results from replaying a test case!`

**Tookan EXTRACTABLE escalation** - `test_tookan.py::TestSensitivePreservation`
- `CKA_EXTRACTABLE` can be escalated on object copy
- A SENSITIVE key can be copied with EXTRACTABLE=True, allowing key extraction
- This is a known class of PKCS#11 key extraction attacks (Tookan, 2010)

### Important

**AES-CTR not functional** - `test_aes_modes.py::TestAESCTR`
- AES-CTR roundtrip, different keys, and non-block-aligned all return `CKR_GENERAL_ERROR`
- If CKM_AES_CTR is advertised, it should work or return `CKR_MECHANISM_INVALID`

**EdDSA signature failure** - `test_eddsa.py::TestEdDSASignVerify`
- Signature length test returns `CKR_GENERAL_ERROR`

**Session login not shared** - `test_session_state_machine.py::TestConcurrentSessionLogin`
- Login on session A not visible on session B
- Per PKCS#11 spec, C_Login applies to the token, not individual sessions
- Session B should see private objects after session A logs in

**CKA_KEY_GEN_MECHANISM incorrect** - `test_attribute_enforcement.py::TestKeyGenMechanism`
- Imported keys report CKM_AES_KEY_GEN (0x1080) instead of CK_UNAVAILABLE_INFORMATION
- Per spec, imported keys must not claim they were generated by a specific mechanism

**Key extraction offset error** - `test_misc_kdf.py::TestExtractKeyFromKey`
- Extract key at byte boundary returns data from wrong offset
- Expected bytes at position 16, got bytes from position 0

**Session objects not visible across sessions** - `test_access.py::TestMultipleSessions`
- Objects created in one session not visible in another session of the same application
- Per spec, session objects should be visible to all sessions in the same context

### Minor

**Hash-ML-DSA returns GeneralError** - `test_hash_ml_dsa.py`
- All Hash-ML-DSA variants fail with CKR_GENERAL_ERROR on empty messages
- Either implementation is incomplete or the mechanism should not be advertised

**Attribute fuzz failures** - `test_attribute_fuzz.py`
- Empty values and wrong-size attributes return CKR_GENERAL_ERROR instead of CKR_ATTRIBUTE_VALUE_INVALID
