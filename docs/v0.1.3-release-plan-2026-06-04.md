# v0.1.3 Release Plan — faster / better / more stable (2026-06-04)

Target: ship v0.1.3 that is **faster**, **more correct**, and **more stable**
than v0.1.2, and good enough to be a **base other tools build on** (they consume
its JSON results, exit codes, pytest plugin, and raw bindings). Synthesized from
five deep gap analyses + a code review across all three lanes (perf, fix-phase,
usability), under the fixed constraints: **K=4 max, no duration-based sharding,
no parallel image builds** (all three confirmed correct by the evidence below).

- **Suite-side gap triage** (extra-session CKR_SESSION_COUNT handling, idempotent
  subprocess cleanup, proxy isolation, capability guards) — `6d9fc7cc`.
- **Single-run perf**: per-subprocess plugin autoload-off; `slow` profile +
  `--skip-slow`/`--only-slow`; vector + collection caches (private, marshal/JSON).

## FASTER (perf — K=4, no durations, no parallel builds)

Constraints confirmed by evidence:
- **Parallel image builds: not worth it.** Every compile already saturates all
  cores (`make -j$(nproc)`, `cargo --release`, ninja, dotnet `/m`); parallelizing
  the build loop is oversubscription. Pivot to *reducing* build work instead.
- **Durations don't transfer across providers** (`test_parameter_validation.py`
  = 553 s on bouncyhsm, 16 s elsewhere — driven by available mechanisms). The
  LPT/`duration_by_unit` path stays off.
- At K=4 the pool wall ≈ W/4, so **reduce W or tighten the tail** — not add K.

| # | Lever | Effort | Impact | Risk |
|---|---|---|---|---|
| F1 | ✅ **T4 streaming postprocess** (shipped) | — | lifts memory ceiling | none (reviewed) |
| F2 | **Scope the NSS slot0 passes** to slot-0-unique files | Med | **~930 s W → ~232 s off K=4 wall**; proven node-level coverage-neutral | Low |
| F3 | **Widen `DEFAULT_HEAVY_BASENAMES`** (add `test_parameter_validation.py`, `test_ccm.py`, `test_wycheproof_*`, `test_acvp_*`, `test_dsa_complete.py`, `test_wrap.py`) | **Low** | fixes the bouncyhsm 1270 s straggler → 842 s; duration-free | Low |
| F4 | **Shared per-distro base image** (2 bases vs ~15 rebuilds of uv/uv-sync/test-tools) + **BuildKit `--mount=type=cache`** (cargo/dnf/apt/uv) | Med | large cold-build / CI-build W | Low |
| F5 | **Readiness polls** (bouncyhsm `sleep 4` → curl-poll; opencryptoki/tpm2 sleeps) | **Low** | ~30 s/run | none |
| F6 | (Lower) extend `REQUIRED_MECHANISMS` coverage so more of the 224 non-declaring files get the cheap file-level skip (no subprocess) instead of per-subprocess runtime skips; shared collection-cache volume; vectors→marshal at fetch; artifacts tmpfs+gzip | Med | incremental | Low |

**Rejected (with evidence):** raise-K (forbidden), duration-based sharding
(non-portable), parallel builds (oversubscription), MCT split (at K=4 nothing
exceeds W/4, so it doesn't lower the wall).

**F2 detail (the headline W cut):** the 3 `-slot0` passes re-run the full suite;
node-level analysis shows ~456 s/474 s/392 s of each is byte-identical re-runs of
the slot-1 pass (0 slot0-only active nodes in the redundant files, 0 outcome
disagreements). Only ~63 s/pass is slot-0-unique (digest/hash/bulk-cipher/KDF,
~39 files). Scope the slot0 pass to those ~39 files. Keep the slot-1 passes (they
uniquely cover login/wrong-PIN and one padding-oracle finding). Cleanest as a
target-subset or a `slot0`/digest marker.

## Suggested v0.1.3 execution order

1. **B1 (PC-6)** — small, closes the last classification gap. Ship first.
2. **F3 + F5** — cheap, high-leverage perf (straggler fix + readiness polls).
3. **F2 (NSS slot0 scoping)** — the headline coverage-neutral W cut.
4. **S1 + S2 + S5** — the usability unlock (doctor + clean errors + quickstart);
   the biggest "base for other tools" enabler.
5. **S4 + S3** — default-profile decision + contract freeze (must precede 1.0).
6. **F4** — build base image + cache (cold-build W).
7. **B2 (Docker rerun)** — regenerate the v0.1.3 release numbers + validate that
   the shipped fixes cleared the stale findings.
8. Tag **v0.1.3**, update CHANGELOG + the release statistics.

Each code change keeps the project rules: never hide a finding; every harness
fix gets a regression test; coverage-neutral perf only (the `slow` profile is
opt-in selection, never a silent drop).
